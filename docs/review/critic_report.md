# Stage 7 · Critic Review

- 目标：`README.md`（全文，FeatureRange）
- 标准：`resources/document_standards/feature-spec-standard.md`
- 审查者：egm-design（设计）、egm-structural（结构）、egm-style（语言）

## 汇总结论：不通过（7 Blocker / 31 Major / 14 Nit）

三位审查者在同一处汇合：**文档把"未强制的性质"写成了"已保证的性质"**，共 4 处（失败不写盘、原子替换、表格可用、配置对称）。这不是措辞问题，是承诺与实现不一致。

---

## A. 设计（egm-design）

### D1 [Blocker] 替代方案完全缺席
- 全文；§1、§6、§7
- 标准的 Alternatives Rule 一次都没执行。被跳过的是本项目的根本决策：进程内 ACadSharp 重写 vs 驱动无界面 AutoCAD。
- 刺眼之处：§7 的验证方法就是 `accoreconsole.exe` + LISP 导出组码——项目自己证明了"不打开 GUI 的 AutoCAD 批处理"在本机可用，它保留事务、图案库、动态块、打印样式、表格、PURGE，恰好是 §6.2 那 13 条降级项的来源。
- 缺的对照：`accoreconsole` + SCR/LISP（能力完整，需授权与安装）、ODA/Teigha（许可成本）、DXF 往返（丢精度）、ACadSharp（§6 那一节）。没有这张表，§6 读起来是"损失清单"而不是"选型结论"。

### D2 [Blocker] "失败即不写盘"被代码否认
- §6.2 L270、§9 L551–555、§10.3 L597
- 代码自己打印：`规则「{0}」中止且 ContinueOnError=false，后续规则不再执行（已完成规则的修改仍会写出）。`（`BatchRunner.cs:133-135`）
- 写出路径没有任何 `summary.Aborted` 门禁：`runner.Run()` 之后无条件 `session.Save()`。
- 真实语义：规则抛异常 → 被 `ExecuteRule` 的 catch 吞掉 → 继续 → **写盘**。回滚边界不是"文件"，是"写盘调用"。
- §10.3 "中途抛异常就不写这个文件"最误导：最可能抛异常的位置正是规则内部，而那里恰好被吞掉。

### D3 [Blocker] 整文件重写会丢未建模对象，全文无此风险
- §9、§6.2、§6 L253
- 每次运行都是"读全图 → 改内存 → 写全图"。ACadSharp 是部分实现，读不出的对象只进 `ReadNotices`，而 `Program.cs:234-237` 的处理是"打一条告警，继续"，随后照常 `Save`。
- 对自称"不可逆、默认值取安全侧"的工具，这是首要失效模式：带 Civil3D/天正/自定义对象的图，跑一条无关的文字替换就可能丢整批对象，而 `AUDIT 0 错误` 不会报——它们已经不存在了。
- 无风险条目、无缓解（阈值门禁、`--refuse-on-warnings`、写前写后对象计数对比），却声称 §6 "全部经过实测确认"。

### D4 [Blocker] 缺 problem statement / goals / non-goals / 成功判据
- 全文结构（§1 直接进入"和 legacy 的关系"）
- 缺"要解决谁的什么问题"、"决定不做什么"（§6 是"做不到什么"，不是"决定不做什么"）、"做对了的判据"（§7 的 `AUDIT 0 错误` 是"没写坏"，不是"改对了"）。
- 后果具体：因为没写非目标，"未引用块定义要不要改""表格单元格要不要碰"只能靠代码现状倒推。

### D5 [Major] 区域过滤对无包围盒对象是 fail-open，文档写反了
- §6.2 L284、§4 L187–189；`SpatialFilter.cs:288-292`
- `Accepts()` 拿不到包围盒时 `return true`，注释写"保守放过"。于是"只处理这块区域"的真实语义是"区域内 + 所有拿不到包围盒的对象"。
- 文档写"表格不参与区域过滤"，读者会理解成"被排除"，方向相反。

### D6 [Major] 三层空间过滤不能单独作为过滤条件
- §4 L180–192、§9 L556–557；`EntityFilter.cs:33-40`
- `HasCondition` 只看类型/颜色/图层/块名/真彩色，不含空间三件套。7 条规则在 `HasCondition==false` 时主动中止。
- 于是"只处理落在 TB-2025 图框里的对象"若没同时写 `EntityTypes`，会得到"规则没有任何过滤条件，已中止"。

### D7 [Major] 回滚只在"运行完整结束"后存在
- §3 L133–145、§7.8；`Program.cs:168-181`
- manifest 在所有文件处理完之后才写。跑到第 300/500 个文件被 Ctrl-C 或崩溃时：文件已覆盖、备份在 `backups/`，但**没有 manifest**。文档反复强调"不靠猜 .bak"，而工具在这种情况下主动放弃了能力。

### D8 [Major] "原子替换"只在 `File.Replace` 快路径成立
- §9 L555；`CadFileSession.cs:289-296`
- 三条分支只有第一条原子：`File.Replace` 失败 → `Copy → Delete → Move`（中间态：目标不存在）；`createBackup=false` → `Delete + Move`（同样中间态）。
- 最需要它的模式（原地覆盖、无备份）恰恰不成立。

### D9 [Major] 表格单元格四处口径不一致，且探测不参与执行
- §5 L239"可用" / §6.2 L283"支持但需回归" / §3 L121"未测" / §10.6 暗示前置检查约束执行
- `CapabilityProbe` 全项目只有一个消费者（`TextMaskRule` 的 Wipeout 探测）；`TextReplaceRule` 无条件遍历表格单元格。

### D10 [Major] §1 "两边配置完全一致"不成立
- legacy 只有 11 种规则类型；新配置里的 9 种在插件里走"未注册 → 中止"（`legacy/Core/RuleFactory.cs:126`、`BatchRunner.cs:198-205`）。字段层面靠 `JsonExtensionData` 保住了往返，**类型层面是单向的**。

### D11 [Major] §7 的验证数字没有定义且互相矛盾
- §7.4 匹配 299 = 2 + 297 ✓；§7.5 匹配 90 ≠ 71 + 228。
- 不变量"匹配 = 成功 + 跳过 + 失败"在 `TextMaskRule` 里被破坏：`MarkSkipped` 发生在 `result.Hit()` 之前。

### D12 [Major] §7.1 "恰好 6 行不同"是把交付缺陷当通过证据
- 223 行填充清单只有 6 行变化 → 输出里同一图案名一半新一半旧，若目标是"统一成 JIS_LC_8A"，这个输出没达成目标。
- 文档用"与插件一致"解释——那是继承理由，不是设计理由。真正该论证的是"未引用块定义该不该归一化"，以及它与 `PurgeUnused` 的顺序依赖。
- `AUDIT 0 错误` 证明"没写坏"，被当成"改对了"的证据，中间隔着一整层。

### D13 [Major] 规模与资源维度整体缺失
- 唯一性能数据是单文件 2568KB / 11419 实体；无内存上限、批量吞吐、超时、取消语义、并发度。
- "Parallel 降级"只论证了文档内并发，从未讨论**文件级并行**（500 个独立文件是天然并行单元）。把"没做"写成"能力边界"。

### D14 [Major] 图案库解析不可复现、不可观测
- §2.2；`ResourceLocator.cs:186-203`
- 第 4 档"本机 AutoCAD"扫 `%ProgramFiles%\Autodesk\AutoCAD *` 取最高版本；无任何日志说明用了哪份 `.pat`；`patterns` 只打印图案名不打印路径。
- 不同版本 `acadiso.pat` 内容不同 → 同一配置在开发机与服务器上写出的图案几何可以不同。文档写"生产环境不要依赖"，但没有开关、没有告警。

### D15 [Nit] §9 护栏清单漏 3 条规则（实际 7 条）
### D16 [Nit] §3 选项表漏 `--no-manifest`（而它恰好关闭回滚能力）
### D17 [Nit] 退出码表按全局陈述，`preflight`/`rollback` 语义不同
### D18 [Nit] §6 开头"全部经过实测确认，不是推测"是不可证伪的全称断言

## C. 语言（egm-style）

### Y1 [Blocker] 状态词表缺失
- 6.2 "状态"列混用 8 种说法（不可用/降级为 Sequential/不支持/不处理/默认不支持/默认不处理，可选/不可控/支持但需回归/无）。这一列是投产判断的唯一依据，但词表未定义。
- 修法：固定三值 `可用 / 降级 / 不支持`，把"可配置开启"与"未验证"拆成独立列，并在表前定义每个值对应的运行时行为。

### Y2 [Blocker] 同一开关两个字段名（`DimensionTextMode` vs `DimensionMaskMode`）
- 照 §4 写配置会得到不生效的键；`JsonExtensionData` 又会原样接住并写回 → "配置看起来对、行为没变"，且不报错。

### Y3 [Blocker] "组码逐字节相同"与 §7.3 数据自相矛盾
- §6.4 称"与源文件组码逐字节相同（都是 45=-2.12132 46=2.12132）"，而 §7.3 明确 `41=1.0 → 41=0.384615`。收窄为"45/46 相同；41 由 1.0 改为 0.384615"。

### Y4 [Major] §4 自称配置参考却只覆盖 9/20 条，默认值披露不一致
### Y5 [Major] 单位缺失（`AuditTolerance` 0.5 是图形单位还是字高倍数？`ZeroLengthTolerance`、`MaskPadding`、`MaskPaddingRatio`）
### Y6 [Major] "结构完全一致"与 6.2 降级清单冲突（结构一致 ≠ 语义等价）
### Y7 [Major] "可跑在服务器、CI"未限定平台（CLI 是 `net8.0`，UI 是 `net8.0-windows`）
### Y8 [Major] 资源文件前置条件三处口径不同，`.lin` 查找顺序缺失
### Y9 [Major] "主动中止"只列 4 条，其余 16 条行为未声明
### Y10 [Major] §7.4 与 §7.5 的"匹配"分母不同，7.5 内部加不平
### Y11 [Major] §7.2 的 `n/m` 未说明分母口径

## 复核意见（Elephant）

D2/D8/D10/Y2/Y3 是**事实性错误**，必须改。D5/D6/D7/D9 是我实现里的真实缺陷，文档只是照实写了错误的一面——要改的是代码或同时改两边。D1/D4 成立：README 确实不是 feature spec，是"使用手册 + 实验记录"的混合体，补一节选型与非目标成本很低。D3 我无法在无宿主条件下验证"未建模对象是否被丢弃"，只能标为未验证风险。Y1 的三值词表是最小改动、最大收益的一条。
